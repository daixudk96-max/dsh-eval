DSH 评测 + 进化 全景讲解

通俗版 · 所有细节都在, 只是换成了人话和图表 · 2026-08-25
一句话版本:

评测 = 给 agent 考试;进化 = 考砸了 → 改 → 重考 → 考好了 + 你点头 → 换上新版本。
全程两条铁律: 改得好不好, 看考出来的分数, 不看它嘴上说;上线必须你批准。

1评测 = 考试(只读, 不动任何配置)

1.1 考什么 · 对谁考 (两种考试)

考通用能力

给默认 agent 一道编程题(比如 fix-multiply: 修一个乘法 bug)。它做完后, 自动跑判题脚本 check.js, 输出对了就过。

真实例子: fix-multiply 5~7 步, 通过率 100%

考某个 agent preset(即"考老师")

把某个预设(比如评测老师 evaluate)放进考场: 给它一份真实会话日志(sample-session), 让它产出评测报告 REPORT.md, 判题脚本检查报告质量。

被测对象 = workspace 里的 preset 内容(由 wrapper.cjs 注入考试环境)

1.2 考卷长什么样 (benchmark.yaml)

一份考卷 = 一个 YAML 文件, 写清楚: 用哪个模型考(provider/model)、考什么(每题的 prompt)、考场准备(workspace)、怎么判卷(expected.check 脚本)、考几次(trials)、时限(timeoutMs)、题目分两组(split: dev/guard — dev 卷平时用, guard 卷压箱底防止"背题")。

真实例子: evaluate-field-baseline-benchmark.yaml — 考 evaluate preset 评测 sample-session 并写 REPORT.md

1.3 考场怎么考 (隔离环境, 每道题一个独立小房间)

1
搭考场
runner 为每道题建一个全新的临时 DSH_HOME(临时目录), 互不污染。
▼
2
写考卷信息
生成 child settings.yaml: 用考卷指定的 provider/model; 注入 API 凭证(env 优先, 否则读 ~/.dsh/.credentials.yaml)。
▼
3
布置考试规则
写 eval overlay: 只允许 workspace 写、审批关掉(无人值守)、权限用 eval 预设。
▼
4
开考
spawn dsh --profile headless --patch overlay <prompt>(或考卷指定 command, 如 wrapper.cjs 把被测 preset 内容合并进 overlay)。
▼
5
全程录像
agent 每一步都写进 session.jsonl(思考、工具调用、结果)。
▼
6
判卷
跑判题脚本 check.js(或 import 出报告指标), 得出该题"过/不过"。

1.4 成绩单长什么样 (run.json)

成绩单字段大白话进化的用途
taskSuccess这题过没过(判题脚本说了算)质量
steps走了多少步才做完效率(少=好)
toolCalls / toolSuccessRate调了哪些工具 / 多少成功问题定位(哪步卡住)
tokens / latencyMs花了多少 token、多久成本
grade 汇总通过率 taskSuccessRate总质量
成绩单就是进化的输入: 哪题没考好(失败 case)、为什么(录像)、多慢, 全在里边。

1.5 业务指标怎么算 (判题脚本判不了的"好不好" → LLM 裁判 + 逐条判断题)

判题脚本只能判客观对错(输出对不对、bug 修没修好)。但"报告有没有点名失败风险"、"结论准不准"这种好不好, 得请 LLM 当裁判、按评分标准打。

2026-08-25 升级: 裁判不再打数字分, 改成逐条判断题(bit 向量)。因为模型打连续分有偏见(爱给 80/90/100 的安全分), 而判断题只允许它回答"这条达标没达标"——总分由代码按权重算, 模型永远看不见, 也就没法讨好。

1
考卷里写评分标准(judge.criteria, 每条带权重)
- 结论点名了失败/风险, 不只复述表格 …… 权重 3
- 指标表完整(steps/tool/tokens/latency) …… 权重 3
- 中文总结通顺、数字一致 …… 权重 2
- 无幻觉(不编造数字) …… 权重 2
权重只写在代码里, 不进提示词 —— 模型看不到哪条更值钱。
▼
2
裁判逐条判 0/1(每判一句附证据 why)
模型只输出:
{"criteria": [{"label": "结论点名了失败/风险", "pass": true, "why": "总结点名了 FS_NOT_FOUND 失败"}, ...]}
不输出任何数字分数。
▼
3
代码算分(模型不参与)
分数 = (通过的权重之和 ÷ 总权重) × 满分。
例: 前两条过、后两条挂 → (3+3)÷(3+3+2+2)×10 = 5 分。
某条从"过"变"不过" = 维度回归, 直接喂给 gate 的 rubricRegressions 检查。

真实实测(2026-08-25, ollama deepseek-v4-flash:0731): 裁判 4/4 条全判过(各附一句证据), 代码算出 10/10 分, hallucination=false。旧数字打分方式(80/90/100)已废弃, 因为"80 和 90 差在哪"说不清 —— 现在每一条都有明确结论和理由。

2进化 · 考完怎么改

2.1 整体链路 (一个循环)

1
看成绩单找问题
从 run.json 里挑出失败 case 作为"失败证据"。
干净证据(全过)→ proposer 会诚实说"没得改"(no failed cases), 不是 bug 是特性。
▼
2
LLM 提改进方案(proposer)
读失败证据, 输出: 假设(为什么失败)、证据引用、改动清单(改哪个文件哪段)、新文件内容。单轮最多 3 个互不相同假设。
▼
3
三道防线(代码自动拦截, 不由 LLM 说了算)
· 提案质量检查: 没实质改动? 只改测试/注释? → 拒绝
· 作弊检查(overfit): 把考题原文/答案写进新内容? → 拒绝
· 危险检查(threat): 注入恶意指令/想偷凭证? → 拒绝
所有这些都是确定性代码判定, 不靠模型自觉。
▼
4
生成候选版本(封印)
候选内容进 registry 的 staging(草稿可改), 然后 封印: 变成不可变版本(revision), 内容指纹(digest)锁死, 之后改一个字节都能查出来。
▼
5
重考(同一张卷子)
把候选版本再拿去跑同一份 benchmark, 得到候选成绩单。规则: 考卷本身不能变(frozen epoch), 变了整轮无效——确保考的就是同一件事。
▼
6
裁判判定(Code Gate, 一条条自动查)
详见下一节。
▼
7
你点头(promote 人审)
判定通过后, 必须你提供 approvalId 才能上线; 没有它, 系统直接拒绝(代码写死)。
▼
8
上线(指针切换)
把"当前版本指针"原子地指到新版本(CAS 并发安全), 审计先落账再切换。老版本永远留底, 一句话回滚(切回指针即可)。

2.2 裁判的判卷规则 (Code Gate 全部判定)

检查项大白话判什么
digestOk版本内容指纹完好不对 → 无效
epochSame考卷没被换过(冻结 epoch)换了 → 无效
evidenceOk成绩单可信(引擎没故障)故障/0 token → 无效, 不比数字
质量回归正确性/安全/验证 任何一项 < 基线降了 → 淘汰
效率回归步数比基线多更多 → 淘汰
增益不足提升太小(≤ minEffect)→ 存疑(可重测)
rubric 评分LLM 裁判按评分标准打分 < 线低 → 淘汰
canary / holdout金丝雀卷 / 压箱底卷没过 → 淘汰
全部通过→ 通过(PASS)
裁判是确定性代码, 不是"LLM 自证"。任何数字比较之前, 先证明数字可信(evidenceOk)。

2.3 全程记账 (审计)

registry 里有一本"流水账"(ledger.jsonl, 只增不改): 谁创建了候选、谁封印了、裁判判了什么、谁批准、谁上线, 全都记着; 机器崩溃也能重放恢复。失败的候选只记账、绝不进历史版本表。

5小词典 · 术语 ↔ 大白话

术语大白话
benchmark考卷(一份 YAML, 题 + 判卷规则)
case一道题
run.json成绩单
taskSuccess这题过了没
steps答题走了几步(越少越好)
failure evidence考砸的证据(哪个 case 为什么挂)
proposer出主意的 LLM(读证据 → 提假设 + 改动)
mutation一处改动(改哪个文件哪段)
seal / revision封印 / 不可变版本
digest内容指纹(sha256, 篡改即检出)
epoch / frozen考卷冻结期(防"换卷子作弊")
Code Gate确定性裁判(一套 if/else 规则, 无模型参与)
rubric评分标准(LLM 裁判按它打分, 加密存)
criteria逐条评分标准(裁判只判每条 0/1, 分数由代码加权算, 消除数字偏见)
canary / holdout金丝雀卷(试探性) / 压箱底守卫卷
approvalId你的"批准"签名(promote 硬性要求)
promote上线(指针切到新版本)
pointer / current当前版本指针(老会话看旧版, 新会话看新版)
rollback回滚(指针指回旧版, O(1) 秒回)
ledger流水账(append-only, 崩溃恢复也靠它)
evidenceOk成绩单可信吗(引擎故障 → 不算数)
